# Phase 4 — UI Design Contract

> Visual and interaction contract for the "Apply to this job" agent workflow. Generated by gsd-ui-researcher, verified by gsd-ui-checker. No CONTEXT.md and no user available: every choice that would have been a question is listed in "Assumptions for the user to confirm" at the end.

Sources: ROADMAP Phase 4 success criteria 1-5, REQUIREMENTS AGENT-01..06, `app/globals.css`, `components/engine/*`, `app/tools/[slug]/page.tsx`, `app/vault/page.tsx`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-written CSS in `app/globals.css` plus Tailwind v4 utilities; no `components.json`). Do NOT initialize shadcn in this phase. |
| Preset | not applicable |
| Component library | none (plain React client components, native `<details>`, `<button>`, `<textarea>`) |
| Icon library | In-repo composite SVG icons (`lib/toolIcons.ts`, `ToolIcon` in `components/tools/ToolCard.tsx`). Inline SVG at 16px for status glyphs; no new icon dependency. |
| Font | `--font-ui` (set in `app/layout.tsx`), exposed as Tailwind `font-sans`. No new fonts. |

Reuse rules (hard requirements, not suggestions):

- Step artifacts MUST render through existing components: fit check via `ReportView kind="fit"`, tailored resume via `ReportView kind="resume"`, cover letter and outreach via `MessageResultView`. Do not re-implement verdict badges, citation lists, placeholder highlighting, `RunWarnings` or `RunDetails`.
- Existing classes to reuse: `cta-primary`, `cta-secondary`, `cta-lg`, `field-label`, `field-control`, `field-help`, `form-error`, `empty`, `chip`, `tool-hero`, `tool-body`, `crumbs`, `tool-title`. `AccessPanel`/`useAccess` is reused unchanged for free tier / own key.
- New CSS is limited to a small `.agent-*` block appended to `globals.css` (timeline, step card, budget meter, sticky action bar). No new Tailwind theme tokens.

### Placement and entry points

| Surface | Contract |
|---------|----------|
| Route | `/apply` (new page, same shell as the tool page: `Header`, `.tool-hero`, `.tool-body`, `Footer`). Breadcrumb: `All tools / Apply / Apply to this job`. A resumed run lives at `/apply?run={runId}`. |
| Discovery | Appears as a featured card at the top of the first tool grid shelf using `ToolCard` with a composite icon (document + check badge) and tag "Agent workflow", plus a link in the Header primary nav. It is NOT a normal preset (it has no `PresetRunner`). |
| Vault | `/vault` gains one section "Applications in progress" (see Resume below) using the existing `rounded-xl border border-zinc-200 p-5` section pattern and `h2` 15px/700. |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, status glyph gap |
| sm | 8px | Chip gaps, inline button gaps, timeline connector inset |
| md | 16px | Default padding inside step cards, gap between fields |
| lg | 24px | Step card padding on desktop, section padding |
| xl | 32px | Gap between left column and timeline on desktop, `tool-body` top padding |
| 2xl | 48px | Space between workflow and "More tools" |
| 3xl | 64px | Page bottom padding (existing 72px `tool-body` bottom is kept) |

Exceptions:

- Touch targets: every button, checkbox row and the step header toggle is at least 44px tall (existing `cta-*` is 48px, `field-control` 44px). Mobile action bar buttons are 48px.
- Inherited off-scale values already in `globals.css` (6px field-label margin, 14px grid gap, 13px input padding) are not changed and not used in new `.agent-*` rules.
- Sticky mobile action bar adds `env(safe-area-inset-bottom)` to its 16px padding.

Layout:

- Desktop (>= 1024px): two columns `minmax(0, 360px) minmax(0, 1fr)`. Left is sticky (top: `var(--header-h)` + 16px) and holds JD input summary, budget meter, and run controls. Right is the step timeline.
- Tablet/mobile (< 1024px): single column. Order: JD input / run summary, budget meter, timeline, then the sticky action bar.
- 375px: no horizontal scroll, side padding 20px (matches `tool-body`), artifact content wraps (`overflow-wrap: anywhere` on citation and subject lines), the 4-step progress strip becomes a vertical list (not a horizontally scrolling row).

## Typography

Four sizes, two weights on all new Phase 4 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15px | 400 | 1.55 (matches `body`) |
| Label | 13px | 600 | 1.4 (step status text, budget meter, field labels, button-adjacent help; also used 400 for `field-help`) |
| Heading | 21px | 600 | 1.25 (step titles, vault section titles use existing 15px/700 `h2` for consistency inside the vault only) |
| Display | clamp(28px, 4vw, 40px) | 800 (existing class) | 1.1 (page `h1` via existing `.tool-title h1`, which ships at 800; keep the existing class unchanged) |

Weight note: new `.agent-*` rules use only 400 and 600. Existing reused classes keep their shipped weights (`cta-*` 650, `.tool-title h1` 800); this is inherited and not a new weight. Reused artifact components keep their own sizes untouched.

## Color

Existing tokens only (`app/globals.css`). Light theme only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--paper` #ffffff | Page background, step cards |
| Secondary (30%) | `--mist` #f3f4f7 with `--rule` #e4e6eb borders | Left run-summary panel, locked/future step cards, hero band, sticky action bar border |
| Accent (10%) | `--red` #e5322d (hover `--red-deep` #c4241f) | Reserved list below |
| Destructive | `--red-deep` #c4241f, tint `#fef3f2`/`#fecdca` (`form-error`) | Discard run, SKIP-verdict banner border, hard error banner. Never used for the approve button. |

Accent reserved for:

1. The single primary action of the current gate (`cta-primary`: "Approve and continue", "Run fit check", "Resume").
2. The focus ring (`:focus-visible`, 2px `--red`).
3. The active step's number badge fill and the connector segment leading into the active step.
4. The "Apply to this job" `ToolCard` hover and top-card border (existing `.tool-card.is-top`).
5. Link text to `/vault` inside the empty state (existing pattern).

Semantic status colors (carry meaning with an icon AND text, never color alone). All are existing Tailwind palette values already used in the engine components:

| Status | Style | Used for |
|--------|-------|----------|
| Complete | emerald-50 bg / emerald-200 border / emerald-800 text (as in the citations card) | Approved step |
| Needs you | `--mist` bg, 2px `--red` left border | Awaiting approval |
| Warning / stopped | amber-50 / amber-200 / amber-800 (as `RunWarnings`) | Budget stop, skipped-by-verdict (non-error stop), edited-since-generation note |
| Error | `form-error` styling | Failed step |
| Locked / pending | `--faint` text, dashed `#cfd2d9` border (as `.empty`) | Steps not yet reached |

## States

Every state has: visible text (not color only), an icon, and an announcement through the live region (see Accessibility).

| State | Where | What the user sees | Primary action |
|-------|-------|--------------------|----------------|
| Empty (no run) | Page load, nothing in progress | `.empty` card: heading "Paste a job, get a full application", body "We check your fit first, then tailor your resume, write a cover letter and draft outreach. You approve each checkpoint." Below it, `JobInput`. If vault has no resume, add the existing "Make it about you" vault prompt and disable run. | "Start application" (disabled until JD and access ready; "Still needed: ..." line as `PresetRunner`) |
| Running a step | Active `StepCard` | Header status "Running: Fit check" with spinner (CSS, honors reduced motion), skeleton lines (existing `animate-pulse` block), step text from preset (`Drafting, then a second AI reviews it for invented claims...`). Other steps show Locked. Inputs and gate buttons disabled; "Stop run" stays enabled. | "Stop run" (`cta-secondary`) |
| Awaiting approval | Active `StepCard` after step 1, and before step 4 | Artifact rendered, header status "Needs your approval", red left border, `GateBar` focused target. Left panel summary: "Waiting for you. Nothing runs until you continue." | "Approve and continue" (`cta-primary`), "Edit" (`cta-secondary`), "Stop here" (`cta-secondary`) |
| Edited | Any editable artifact or step 1 inputs | Badge "Edited by you" (amber) on the card and in the vault record. Edited text replaces the generated text for later steps (cover letter uses edited resume text). Grounding re-check result shown after Save: if the edit adds an unsupported figure, `RunWarnings`-style amber note "Check before using: {finding}" and Save still allowed. Buttons: "Save edit", "Revert to generated". | "Save edit" (`cta-primary` while editing) |
| Skipped by verdict | After step 1 when verdict is SKIP | Run status "Stopped: this looks like a poor fit." Amber banner (not error): "Fit check verdict: SKIP. We stopped here so you don't spend effort on a long shot. {top 1-2 gaps from the fit result}". Steps 2-4 shown Locked with reason "Skipped because of the SKIP verdict". Override is an explicit second action, never default focus. | "Stop here" is the default and focused; "Continue anyway" (`cta-secondary`) opens inline confirmation: "Override SKIP: Continue anyway? The next steps use your time and tokens even though the fit check says skip. [Continue anyway] [Keep the SKIP verdict]". After override the card shows badge "Verdict overridden by you". |
| Budget exceeded | Run-level | Amber `RunBanner` with `role="alert"`: "Stopped: step limit reached (6 of 6 steps used)." or "Stopped: token limit reached (48,200 of 50,000 tokens)." Completed steps remain visible and usable. Remaining steps show Locked "Not run: budget reached". BudgetMeter turns amber at 80% and shows full bar plus text at stop. Never silent. | "Continue with a new budget" only if free tier daily quota allows (`cta-secondary`); otherwise "Copy what we have" per artifact and "Back to vault". Assumption 5. |
| Error | Active `StepCard` | `form-error` block inside the card with `role="alert"`: "{Step name} didn't finish. {server message}. Your earlier steps are saved." Includes quota/timeout copy from the API unchanged. | "Retry this step" (`cta-primary`), "Stop run" (`cta-secondary`) |
| Resumed | Page opened with a saved unfinished run | Info banner at top: "Welcome back. We restored your application for {role or company, else 'this job'} from your Career Vault. Last activity {relative time}." Completed steps render collapsed-open with artifacts; the interrupted step is shown as the next step with status "Ready to continue" (a step that was mid-run is restarted, not assumed done). Focus moves to the banner heading then the primary action. | "Resume" (`cta-primary`) |
| Completed | Run-level after step 4 | Green summary card "Application ready" with a checklist of 4 artifacts, each with Copy (existing `CopyButton`) and "Jump to step" link. Banner not `role="alert"`; announced politely. Offers "Save to vault" confirmation (already auto-saved; copy says "Saved to your Career Vault") and "Start another job". | "Start another job" (`cta-secondary`); no destructive CTA |

Collapsing: completed `StepCard`s are expanded for the current step and the most recent step, collapsed (`<details>`-style disclosure button with `aria-expanded`) for older steps, header always shows title, status, and time/tokens.

|---------|------|
| Page `h1` | Apply to this job |
| Page lede | Paste a job description. We check your fit, tailor your resume, write a cover letter and draft outreach, and you approve the checkpoints. |
| Primary CTA (start) | Start application |
| Primary CTA (gate) | Approve and continue |
| Primary CTA (resume) | Resume application |
| Empty state heading | Paste a job, get a full application |
| Empty state body | Add the job description above and press Start application. Your progress is saved to your Career Vault, so you can close this page and pick it up later. |
| No resume in vault | Make it about you. Add your resume to your Career Vault first, then every step writes from your real experience, with citations. |
| Running status | Running: {Step name}. {n} of 4 |
| Awaiting approval status | Needs your approval |
| Edited badge | Edited by you |
| Skip banner | Stopped: this looks like a poor fit. The fit check verdict is SKIP, so we haven't run the other steps. |
| Override confirmation | Continue anyway: Override the SKIP verdict? The next steps will use your time and tokens even though the fit check says skip. |
| Step budget stop | Stopped: step limit reached ({used} of {limit} steps). Your finished steps are saved below. |
| Token budget stop | Stopped: token limit reached ({used} of {limit} tokens). Your finished steps are saved below. |
| Error state | {Step name} didn't finish: {reason}. Your earlier steps are saved. Try again, or stop here and keep what you have. |
| Resumed banner | Welcome back. We restored your application from your Career Vault. Pick up at {Step name}. |
| Locked step reason | Waiting for {previous step}. / Skipped because of the SKIP verdict. / Not run: budget reached. |
| Completed | Application ready. All four drafts are saved to your Career Vault. |
| Grounding reminder (under each artifact) | Reused from the standalone tools: claims cite your resume; figures not in your material are flagged. |
| Destructive: Stop run | Stop run: Stop this application? Finished steps stay in your Career Vault and you can resume later. [Stop run] [Keep going] |
| Destructive: Discard run (vault only) | Delete application: Delete this application and its drafts from your Career Vault? This can't be undone. [Delete application] [Keep application] |
| Destructive: Revert edit | Revert to generated: Discard your edits to this draft? [Revert] [Keep my edits] |

Confirmation approach: the existing app uses `window.confirm` for vault replacement. For Phase 4, use an inline two-button confirmation inside the card (not `window.confirm`) for override-SKIP, stop, revert and delete, so focus and copy are controlled; the confirm button for destructive items uses `--red-deep` outline style, never `cta-primary`. The non-destructive choice ("Keep the SKIP verdict", "Keep going", "Keep my edits", "Keep application") receives initial focus.

Focal point: on `/apply` the visual anchor is the active StepCard and its GateBar primary action; in the Completed state it is the "Application ready" summary card. Vault row actions use full labels: "Resume application", "Delete application"; artifact edit uses "Edit draft".

## Interaction Contract

- Start: submit the form (Enter inside textarea inserts newline; button submits). Step 1 begins; timeline appears and focus moves to the live status heading of step 1.
- Gates are the only way forward at Checkpoint A and B. Steps 2 and 3 run automatically after approval of A, with a visible "Pause after this step" checkbox (default off).
- Edit at Checkpoint A means: edit the JD text and optional notes ("Why I want this role"), then "Re-run fit check". This replaces step 1's artifact and invalidates later steps (they are cleared with a visible note "Cleared because the fit check changed").
- Edit on steps 3 and 4: inline `ArtifactEditor` toggled by "Edit"; Esc cancels edit (with confirm only if there are changes); Save re-runs the existing grounding check client/server side and shows warnings.
- Every action is idempotent: double-click on Approve does not double-run (button disabled the instant it is pressed).
- Persistence: run state (steps, tool calls, outputs, edits, budget counters, verdict override) is written to the vault after each step and each edit. A small "Saved to your Career Vault" text with timestamp (Label style, `--faint`) sits in the left panel. Closing the page never loses a finished step.
- Budget meter: two labeled meters, "Steps 3 of 6" and "Tokens 21,400 of 50,000". Native `<progress>`/`role="progressbar"` with `aria-valuenow/min/max` and visible numeric text. Defaults come from the engine config, not hard-coded in UI.
- "How this was generated" (`RunDetails`) appears inside every artifact exactly as in standalone tools; additionally each `StepCard` header has a disclosure "Tool call" showing the tool name, input summary, duration, and token usage (Label style, `<details>`).
- Vault list ("Applications in progress"): rows show job label, status badge (In progress / Needs approval / Stopped / Completed), last activity, and buttons "Resume" (`cta-secondary`) and "Delete" (text button, destructive confirm). Empty copy: "No applications yet. Start one from Apply to this job." linking to `/apply`.

## Accessibility

Focus order (top to bottom, left to right in DOM; DOM order equals visual order, including mobile):

1. Skip link target (existing layout) -> `Header` -> breadcrumbs -> `h1`.
2. Run banner (if present, programmatically focusable `tabIndex={-1}` heading).
3. Left panel: JD field, optional fields, AccessPanel, Start/Resume button, budget meter, Stop run.
4. Timeline `<ol>`: each `StepCard` header toggle, then its artifact content, then its gate buttons.
5. Completed summary, then "More tools".

Focus management rules:

- On step start: focus stays on the control the user pressed unless it becomes disabled; then move focus to the active `StepCard` heading (`tabIndex={-1}`).
- When a gate appears (awaiting approval): move focus to the card heading, and the first button in `GateBar` is "Approve and continue" (except in Skip state where "Stop here" is first and default).
- After Override/Stop confirmations close, return focus to the button that opened them.
- On Resume: focus the "Welcome back" banner heading.
- Do not steal focus on silent saves.

Live regions:

- One persistent `<div aria-live="polite" aria-atomic="true" class="sr-only">` at the top of the timeline announces step progress: "Fit check running", "Fit check finished. Verdict: Apply. Needs your approval.", "Tailor resume finished", "Saved to your Career Vault".
- `role="alert"` (assertive) only for: error state, budget stop, and Skip stop banners. Never both live region and `role="alert"` for the same message (avoid double announce).
- The streaming/skeleton area has `aria-busy="true"` while running.
- Budget meter changes are NOT announced per token; announce only at 80% and at the stop.

Other:

- Timeline is an ordered list `<ol>`; the active card has `aria-current="step"`. Locked cards are `aria-disabled` with their reason as visible text, not `disabled` buttons that drop out of reading order.
- Status uses icon + text; contrast >= 4.5:1 for body text (`--slate` #5e6472 on white passes; `--faint` only for non-essential metadata).
- Targets >= 44px; focus ring is the global `:focus-visible` 2px `--red`.
- `prefers-reduced-motion`: spinner replaced by static "Working" text with a step indicator; skeleton pulse disabled by the existing global rule.
- Textareas have visible labels and `aria-describedby` on `field-help`; edit mode announces "Editing {artifact}" via the live region.
- Keyboard: Esc closes inline confirmations and cancels edit; all gate actions reachable without a pointer.

Mobile at 375px:

- Single column; `JobInput` textarea 6 rows, full width; no side-by-side buttons in cards (stack, each full width, 48px).
- `GateBar` becomes `position: sticky; bottom: 0` with `--paper` background, 1px `--rule` top border, 16px padding plus safe-area inset, containing the primary action and one secondary; the other actions move to an overflow "More" disclosure inside the card. Page bottom padding increased by the bar height so content is never covered; the bar hides while an input is focused to avoid overlapping the keyboard.
- Budget meter collapses into a one-line summary "Steps 3/6 · Tokens 21k/50k" that expands on tap (`aria-expanded`).
- Artifact views are reused as-is; wrap long citation lines, and tables in the fit report scroll inside their own container, not the page.
- Step cards past the current one start collapsed to keep scroll length manageable.

## Assumptions for the user to confirm

1. Route and entry: a new `/apply` page plus a Header/ToolGrid entry, rather than a preset on `/tools/[slug]`. Rationale: the workflow is multi-step and does not fit `PresetRunner`.
2. Gates: required checkpoints at A (after fit check) and B (before outreach) only; resume tailoring and cover letter auto-run with an optional "Pause after this step". Roadmap says "e.g. after fit check, before outreach", so these are the minimum.
3. Editing scope: step 1 edit means editing JD/notes and re-running (since the fit verdict is code-computed from evidence, not hand-editable); cover letter and outreach are editable text; the tailored resume is shown read-only with copy (editing structured resume output deferred).
4. Edits reuse the grounding check and warn rather than block on unsupported figures.
5. After a budget stop, the UI offers "Continue with a new budget" only when quota allows; the budget values (steps, tokens) are engine config, and this spec assumes defaults around 6 steps and 50,000 tokens as placeholders in copy only. Planner should wire real numbers.
6. SKIP override requires a second explicit confirmation and "Stop here" is the default focus. The override is recorded in the vault run.
7. A step interrupted mid-run on close is restarted on resume, not assumed complete.
8. Resume discovery: both via `/vault` "Applications in progress" and automatic offer on `/apply` when an unfinished run exists (most recent one only on `/apply`).
9. Visual language stays light-only, red accent 10%, no new fonts/colors/icon libs; four type sizes (13/15/21/display) and two new weights (400/600), inheriting existing 650/800 on reused classes.
10. Inline confirmations replace `window.confirm` for new destructive actions (the existing vault resume replace keeps `window.confirm`).
11. shadcn is intentionally NOT initialized (the project has none and every existing surface is hand-built).
12. Sharing/export of the whole application (zip/PDF) is out of scope; per-artifact Copy only.
