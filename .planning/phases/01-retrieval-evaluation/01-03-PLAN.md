<feature>
  <name>Retrieval metrics</name>
  <files>evals/retrieval/metrics.ts, tests/retrieval-metrics.test.ts</files>
  <behavior>
    Inputs: `ranked: string[]` (chunk ids in returned order, as the strategy returned them, including the anchored summary at position 1) and `relevance: Map<string, number>` (chunk id -> grade 1..3; missing = 0).
    - RELEVANCE_THRESHOLD = 2: a chunk counts as relevant for recall/MRR when grade >= 2.
    - recallAtK(ranked, relevance, k) = |relevant in ranked.slice(0,k)| / |relevant overall|; 0 when there are no relevant chunks. Case: relevant {a:3, b:2, c:1}, ranked [x, a, y, b] -> recall@3 = 0.5, recall@5 = 1 (c is grade 1, not counted).
    - reciprocalRank(ranked, relevance) = 1 / (1-based position of first relevant), 0 if none. Case: [x, a] -> 0.5; [x, y] -> 0. MRR is the mean over queries; since strategies return at most 8 items it is effectively MRR@8 (document this in a comment).
    - ndcgAtK(ranked, relevance, k): DCG = sum over i<k of (2^grade - 1) / log2(i + 2); IDCG = same over all labelled grades sorted descending, truncated to k; result DCG/IDCG, 0 when IDCG is 0. Case: relevance {a:3, b:1}, ranked [b, a] -> DCG = 1/1 + 7/log2(3) = 5.4165, IDCG = 7 + 1/log2(3) = 7.6309, nDCG@2 = 0.7098 (assert to 4 decimals). Perfect order -> 1. Duplicate ids in ranked are counted once (first occurrence).
    - METRIC_KEYS = ["recall@3","recall@5","recall@8","mrr","ndcg@3","ndcg@5","ndcg@8"] as const; type MetricKey; `type MetricSet = Record<MetricKey, number>`.
    - scoreQuery(ranked, relevance): MetricSet for one query.
    - aggregate(sets: MetricSet[]): MetricSet of arithmetic means (all zeros for empty input).
    - PRIMARY_METRIC: MetricKey = "ndcg@8" with a comment: graded (rewards the evidence bullet over its container), covers the full 8-chunk context the app sends (DEFAULT_VAULT_LIMIT = 8), and order-sensitive because the context assembler may truncate under token budget. Phase 2's reranker adoption decision reads this constant.
    - percentile(values: number[], p: number): nearest-rank percentile on a sorted copy (p50 of [1,2,3,4] = 2, p95 of 1..20 = 19); 0 for empty input.
  </behavior>
  <implementation>Pure TypeScript, no imports from browser modules, no fs. Write tests/retrieval-metrics.test.ts first with the cases above plus edge cases (empty ranked, k larger than ranked length, no relevant chunks), run `npm test` and confirm the new tests fail, commit test; then implement evals/retrieval/metrics.ts until green, commit; refactor only if needed.</implementation>
</feature>
