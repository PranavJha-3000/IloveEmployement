<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model -> policy | The planner's tool choice (steerable by text in a pasted JD) is untrusted and must pass validateChoice |
| client -> policy | Step summaries and approvals come from the browser; the policy is reused server-side so the order rules hold regardless of client UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | validateChoice | mitigate | Only tools in nextAction().allowed are executable; outreach before gate B, skipping fit_check, and early finish are rejected (prompt-injected tool steering cannot bypass order) |
| T-04-02 | Denial of service (cost) | nextAction budget check | mitigate | Step budget 6 and token budget 50,000 stop the loop before a new step; rejected choices count as steps so a model that keeps choosing invalid tools still hits the step budget |
| T-04-03 | Tampering | countUsage with null usage | mitigate | AGENT_NULL_USAGE_ESTIMATE constant is defined here and charged server-side (plan 03) when a provider reports null usage |
| T-04-04 | Elevation | budgetLimits(resets) | mitigate | resets clamped to AGENT_MAX_BUDGET_RESETS so a client cannot request unbounded limits |
</threat_model>
