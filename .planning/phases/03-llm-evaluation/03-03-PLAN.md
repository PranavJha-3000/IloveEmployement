  <action>
    Write evals/llm/RUBRIC.md with these sections, in this order:

    "# LLM judge rubric and metric definitions" plus a status line "Pre-registered: committed before any judged run. Changing this file changes rubricHash and invalidates judge cache entries." and the date.

    "## Inputs the judge sees": the case's user inputs (pasted text fenced as untrusted), the vault chunks supplied to the generator with their ids, the final user-visible output fenced as untrusted model output, and a numbered list of citation units. The judge never sees the generator model id, the behavioural pass/fail, or other models' outputs.

    "## Dimensions (scale 1-4)": exactly three dimensions with ids `groundedness`, `task_fit`, `clarity`. For each, write one sentence of definition and an anchor for each score 1, 2, 3, 4 (1 = unusable, 4 = ready to send). groundedness: every statement about the user traceable to inputs/vault, placeholders used for unknowns; task_fit: does what the tool's task and inputs asked (format, length, audience, verdict sensible); clarity: specific, plain, no clichés or filler. State that 4-point scale has no neutral middle on purpose.

    "## Claims about the user": a claim is an atomic statement of fact about the candidate (employer, title, date, number, skill, tool, achievement, credential, offer term). Not claims: [bracketed placeholders], advice, opinions about the job, statements about the company/job. Label each claim `supported` (stated or directly implied by inputs or vault chunks), `unsupported` (not in the supplied material, or stretched beyond it, e.g. "led" vs "contributed"), with the evidence (chunk id or "input"). Judge lists at most 40 claims per output, longest-impact first.

    "## Citation units": a unit is one (cited item, chunk id) pair from the raw final model output: each `citations[].chunkId` with its `claim`, and each id in a `chunkIds` or `evidencedBy` array with the text fields of the object that holds it. The harness first checks deterministically whether the id was supplied; the judge labels units with supplied ids as `supports`, `partial` or `does_not_support`.

    "## Metric definitions" (precise formulas; these are the numbers reported):
    - Citation id validity = valid-id units / all units (deterministic).
    - Citation precision (strict, headline) = units with a supplied id AND judge verdict supports / (all units minus unjudged units). Invalid ids count as not supporting. Lenient precision counts partial as supporting. Unjudged = valid-id units the judge omitted; reported as a count, excluded from both numerator and denominator. Outputs with zero units contribute nothing; the report shows how many outputs had units.
    - Claim fabrication rate (judged) = unsupported claims / (supported + unsupported claims), pooled over all judged outputs of a model.
    - Output fabrication rate (combined, headline) = share of judged outputs where the judge found at least one unsupported claim OR meta.grounding contains an invented-figure warning. Deterministic-only output rate (figure check alone) is reported beside it.
    - Judge dimension score = mean of the 1-4 scores per model over judged outputs.
    - Behavioural pass rate = cases whose deterministic expect returned no failures / cases attempted; errors count as failures and are also counted separately.
    - Tokens: prompt, completion and thinking (when the provider reports thoughtsTokenCount) summed over every call for the case, reviewer and revision included; judge tokens reported separately.
    - Latency per case = sum of recorded model-call latencies for the case (throttle waits and backoff excluded; cached calls replay their original latency). p50/p95 by nearest rank over cases.
    - Estimated cost = tokens x list price from evals/llm/prices.ts (thinking tokens billed at the output price); free-tier billed cost is $0 and both are shown.

    "## Agreement with human labels": the human labels about 30 outputs blind to judge scores and model ids, on the same three dimensions, a fabrication-present yes/no, and support verdicts for up to 5 citation units per output. Reported: quadratic-weighted Cohen's kappa, exact and within-1 agreement per dimension; Cohen's kappa and raw agreement for fabrication-present and for citation support (strict: supports vs not); 95% percentile bootstrap CI resampling outputs, 10000 iterations, seed 20261101. Kappa is "n/a" when expected agreement is 1.

    "## Known limitations": judge in the same model family as the generators has self-preference bias; single run; small n.

    Create evals/llm/rubric.ts exporting `RUBRIC_DIMENSIONS = ["groundedness", "task_fit", "clarity"] as const`, `type RubricDimension`, `SCORE_SCALE = [1, 2, 3, 4] as const`, `CITATION_VERDICTS = ["supports", "partial", "does_not_support"] as const`, `CLAIM_STATUSES = ["supported", "unsupported"] as const`, `AGREEMENT_SEED = 20261101`, `BOOTSTRAP_ITERATIONS = 10000`, `loadRubric(path = "evals/llm/RUBRIC.md"): string` (fs read relative to process.cwd()), and `rubricHash(text): string` (contentHash).
