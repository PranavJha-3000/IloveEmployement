<objective>
Build the stateless one-step server: POST /api/agent/step receives the run state, asks the planner model for the next tool via Vercel AI SDK tool calling, validates the choice with the shared policy, executes it through the existing runPreset, and returns the step result plus budget accounting.

Purpose: AGENT-01 (bounded tool-calling loop over existing engines), AGENT-02 (budgets enforced server-side), AGENT-04 (gates enforced server-side), AGENT-05 (every artifact goes through runPreset, so grounding guarantees are identical to the standalone tools).
Output: run.ts seam, schema.ts, planner.ts, step.ts, route.ts, plus two pipeline tests guarding the run.ts change.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/agent/step | Whole run state (steps, budget claims, approvals, vault chunks, optional BYOK key) is untrusted |
| pasted JD -> planner model | JD text can contain instructions aimed at tool choice |
| planner model -> tool execution | Model output selects a tool and enum args |
| server -> provider | BYOK or free-tier key used for provider calls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Tampering | parseAgentStepRequest | mitigate | zod schema with max lengths on every string/array, enums for tools/status/verdict/channel; 400 with generic message, body never echoed |
| T-04-10 | Tampering (prompt injection) | planner + validateChoice | mitigate | JD passes screenUntrusted and is fenced as untrusted_document; tool params are enums only; validateChoice rejects out-of-order tools; the chosen preset reruns the existing injection gate on the JD field (untrusted: true) |
| T-04-11 | Denial of service / cost | agentStep budget + free tier | mitigate | Budget recomputed from step records with Math.max over client claims; blocked actions return before resolveAccess and before any model call; each executed or rejected step increments the per-IP free counter exactly once via a single resolveAccess; route maxDuration 60 |
| T-04-12 | Elevation | client-claimed budget limits | mitigate | Limits come only from server constants via budgetLimits(resets) with resets capped by zod; opts.limits is not reachable from the route |
| T-04-13 | Information disclosure | BYOK key | mitigate | Key only used in-request via resolveAccess; errors go through classifyAIError redaction (runPreset); no logging in route/step; key never copied into step records (inputs are tool fields only) |
| T-04-14 | Spoofing | approvals in client state | accept | Approvals are the user's own choices about their own run; the server only guarantees order (fit first, outreach after gate B), which the model cannot forge |
| T-04-15 | Tampering | client edits its own step summaries (e.g. drops records to reset usage) | accept | Residual: stateless server cannot prove history; abuse of shared resources is bounded by the per-IP daily free-tier counter, and BYOK users only spend their own quota |
</threat_model>
