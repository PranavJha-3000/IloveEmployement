## Code Review Findings: criterion versus follow-up

- **WR-01 (gate covers keyword only):** Not a gap. SC4 and REVAL-04 explicitly specify keyword-only metrics in CI without network. The semantic and hybrid paths are covered only by parity tests, which is a real protection gap that Phase 2 (reranking) should close, but it is outside this phase's contract. Follow-up.
- **WR-02 (baseline fails open on missing keys or NaN):** Hardening. The gate works for the recorded baseline, and the run and unit tests confirm both the pass and fail paths. A hand-corrupted baseline could pass silently. This is a robustness defect, not an unmet criterion. Follow-up, and cheap to fix.
- **WR-03 (baseline rewrite hides regressions):** Process weakness. SC4 requires failing "against the recorded baseline", which it does. Follow-up.
- **WR-04 (paraphrase keyword baseline is 0 by construction):** Not a gap. SC1 requires paraphrase queries "sharing no keywords with their targets", so keyword scoring 0 on them is the intended result. The consequence is that the paraphrase gate scope is inert and the Overall table reflects the query mix. The lexical scope keeps the gate meaningful. Follow-up: drop or relabel the paraphrase gate scope and lead the report with the per-type tables.
- **WR-05, WR-06, IN-*:** Test and cache quality items. None block a criterion. A caveat on IN-03: the committed report cites sha 3fe9ab7 and may have been generated from a dirty tree.
