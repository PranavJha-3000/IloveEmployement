Flow: loadDataset() (on DatasetError print every problem, exit 1). If any selected strategy needsEmbeddings, `await import("./embedder")` (dynamic, so keyword-only runs never touch the transformers package), create the embedder, embed every corpus once (cached), and on failure print "Embedding model unavailable (needs network on first run): <message>" and exit 1. For each query: if needed, embed the query once and record embedMs; for each strategy call retrieve() `repeat` times with `limit: 8`, recording the median rankMs (performance.now()); totalMs = rankMs + (needsEmbeddings ? embedMs : 0); score the returned ids with scoreQuery against the query's relevance map. Aggregate per strategy overall, per query type (lexical, paraphrase) and per resume; latency p50/p95 of totalMs and p50 of embedMs per strategy via percentile(). Print a console table of the overall metrics per strategy.

    Results object (exported type RetrievalRunResult): generatedAt ISO, command (process.argv slice joined), gitSha (execSync "git rev-parse --short HEAD", "unknown" on failure), node version, platform, dataset { fingerprint, resumes: [{ id, seniority, domain, chunks }], queries, lexical, paraphrase }, embeddingModel { id, dtype } or null, primaryMetric, relevanceThreshold, strategies: [{ id, label, overall, byType, byResume, latency { p50, p95, embedP50 }, perQuery: [{ id, type, metrics, rankedIds, totalMs }] }]. Write it to evals/results/retrieval-<timestamp>.json and evals/results/retrieval-latest.json (mkdirSync recursive). In non-ci mode also write the markdown from renderReport to the --report path.

Numbers below come from evals/results/retrieval-latest.json of the same run."; run facts (date, git sha, node, platform, embedding model, dataset fingerprint); Dataset (resumes with seniority/domain/chunk counts, query counts by type); Method (one bullet each: per-resume corpora as in the app's single-user vault; strategies call retrieveVault / semanticRanking / reciprocalRankFusion from lib/; limit 8 = DEFAULT_VAULT_LIMIT; the app always anchors the summary at rank 1 and keeps max 3 chunks per role, and the metrics include that behaviour; relevance grades 1-3, recall/MRR count grade >= 2, nDCG gain 2^g - 1; MRR is effectively MRR@8; latency = median of --repeat timed calls per query, including the query embedding for embedding strategies, chunk vectors precomputed as in the app's index; primary metric ndcg@8 and why); "Overall" table (rows = strategies, columns = METRIC_KEYS with the primary column header bolded, values to 3 decimals); "Lexical queries" and "Paraphrase queries" tables in the same shape; "By resume" table of the primary metric; "Latency" table (strategy, p50 ms, p95 ms, query-embed p50 ms, to 2 decimals); "Misses" list: queries where every strategy has recall@8 = 0, with id, type and query text (empty-state line when none). Values are formatted only from the result object; no constants typed in by hand.
