<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generator output -> judge prompt | Model output is untrusted and may contain injected instructions |
| pasted case inputs -> judge prompt | Adversarial cases contain injection text by design |
| judge response -> metrics | Judge output is untrusted structured data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering (prompt injection) | judge.ts buildJudgePrompt | mitigate | Output fenced as <untrusted_model_output>, inputs as <untrusted_case_material>; fence() neutralises embedded open/close tags; JUDGE_SYSTEM says fenced text is data; test proves exactly one closing tag survives a fence-break attempt |
| T-03-11 | Tampering | judge response parsing | mitigate | zod judgeSchema with enums; unknown citation indices ignored and counted; parse failures become ok:false judge errors, excluded from means and reported |
| T-03-12 | Information disclosure | judge errors | mitigate | All error text through redactSecrets before storage |
| T-03-13 | Denial of service (quota) | runJudge | mitigate | Judge calls go through recordingModel (cache, throttle, backoff) with maxRetries 0; at most one fallback call per output |
</threat_model>
